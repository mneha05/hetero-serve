hetero-serve

CUDA · distributed inference

When a request shares a long prefix with an earlier one — a system prompt, a RAG document, an earlier turn — its KV cache already exists, but on the wrong accelerator. Run it where the cache is and queue behind a busy device, recompute the prefix, or drag the cache across the interconnect? That is a bandwidth-versus-compute trade, and this is a serving system built to find where it flips. A paged KV cache with 16-token blocks, refcounts, chain-hashed prefix sharing and LRU eviction; continuous batching with chunked prefill and recompute-preemption; and a router that prices stay against migrate in seconds using device speeds it measures at startup rather than assumes. Workers are real OS processes over real TCP through a token-bucket shaper, so transfers genuinely contend — at 50 Mbps moving an 18.9 MB prefix loses to recomputing it, at 10 Gbps it wins, and cache-aware routing cuts end-to-end p50 from 3.60 s to 1.94 s.

Then profiling said a third of every decode step was not accelerator time at all — it was the host gathering KV blocks into contiguous tensors, overhead invented by paging the cache. So I wrote the kernel that deletes it, and then four more. Nsight showed the online-softmax kernel was occupancy-starved rather than bandwidth-starved — 0.1 waves across 40 SMs — which produced a context split that took it from 13.4% to 55.4% of a Tesla T4's peak memory bandwidth, or 10–22× PyTorch's own SDPA on paged data. Sweeping the split count then caught my own heuristic being wrong: it targeted occupancy and chose 2 where 32 was 2.1× faster, because the online softmax is sequential and splitting shortens a dependent chain, not a wave count. There is a prefill kernel too, and a tensor-core version where a 16-token KV page is exactly one 16×16×16 WMMA fragment — which is why that block size was the right default before any kernel existed.

101 tests, no mocks — real processes, real sockets, kernels fuzz-tested against a numpy oracle and against each other. Five bugs are documented, every one found by measuring rather than reading; the one worth keeping is the time I was certain the cause was a serialisation layout, benchmarked it first, and was wrong.

Inference Engine

CUDA · from scratch

An LLM served by code I wrote at every layer — no PyTorch, no frameworks, just raw CUDA. I hand-wrote the kernels a modern inference stack is built on: fused attention to kill memory-bandwidth waste, a paged KV-cache so long contexts don't blow up VRAM, INT8/INT4 quantized matmuls, and speculative decoding to draft-and-verify tokens in parallel. Figment

market microstructure

A trading simulator for Figgie — the card game Jane Street built to teach market intuition — engineered from the matching engine up. Underneath: a continuous double auction with four independent order books, price-time priority, and exact settlement. On top: a market maker that doesn't guess — it maintains an exact multivariate-hypergeometric posterior over which suit secretly scores, prices every card at expected value, and quotes two-sided Avellaneda–Stoikov, skewing on inventory and widening spread with belief entropy. An evolutionary self-play loop lifts it from +$6 to +$37/game over 14 generations. The punchline that makes it click: the noise traders win more pots yet lose money every game — because they overpay. Edge ≠ outcome.

PARALLAX

multi-agent systems

Most "AI agents" summarize a problem. This one investigates it. A director agent decomposes a reliability incident into a task graph and fans out specialized statistical worker agents in parallel, each sandboxed with its own toolset and context. Their findings flow back through a cross-validation layer that reconciles conflicts before synthesis — because a multi-agent system without verification is just N chances to hallucinate. Per-worker fault isolation means one agent dying never kills the investigation, and every conclusion ships with linked evidence. Hypothesis generation, statistical testing, dead-end pruning — autonomously.

Sentinel

real-time telemetry

A triage room for streaming sensor telemetry. It ingests many channels at once and classifies every deviation as noise, drift, or imminent failure — then runs cross-channel correlation to answer the question that actually matters: is this one sensor dying, or the whole system? Built around a hard-won production truth: alert fatigue kills monitoring faster than missed alerts do. So every flag arrives with its supporting evidence, its correlated channels, and a recommended action — the human stays in the loop deciding, not deciphering. Explainability here isn't a feature bolted on; it's the architecture.

VibeGraph

compiler techniques

An IDE for agentic workflows where the YAML source and the visual DAG are two projections of one canonical state — edit either, and a bidirectional reconciliation engine syncs them in real time with no drift and no destructive rewrites. The real engineering is underneath: a custom static analyzer that performs variable scope resolution and data-flow validation across steps, catching broken references before anything runs — compiler techniques aimed at workflow definitions. Plus a step-through simulator that debugs agent pipelines like code (breakpoints, state inspection, deterministic replay). 33 passing tests, because developer tooling doesn't get to be flaky.

I have spinal stenosis, so I built the thing I wished existed. A wearable that watches posture in real time and nudges me the instant I start to slump — before it becomes pain I pay for later.
